# Xscriptor Build & Deployment

Everything needed to build, validate and ship xscriptor.com, plus the static
hosting contract. The site is a **100% static export** — there is no server
runtime, no PHP and no API.

---

## 1. Scripts (`package.json`)

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "next lint",
    "postbuild": "next-sitemap"
  }
}
```

- `npm run dev` — local dev server on `http://localhost:3000`.
- `npm run build` — production build. `next build` writes the static site to
  `out/`, then `postbuild` runs `next-sitemap` (npm automatically runs
  `postbuild` after `build`).
- `npm run start` — serves the production build locally (not used in
  production; the site is static).
- `npm run lint` — `next lint`. On Next 16 this can be unreliable; the
  project’s actual validation is TypeScript:

  ```bash
  npx tsc --noEmit
  ```

Requirements: Node 18+ and npm. No environment variables are required.

## 2. Next.js configuration

`next.config.ts`:

```ts
const nextConfig: NextConfig = {
  output: "export",        // static HTML export to out/
  trailingSlash: true,     // every route emitted as /path/index.html
  images: { unoptimized: true },  // no Image Optimization API at runtime
};

export default nextConfig;
```

Consequences:
- **Every route must be statically renderable.** Do not add route handlers,
  middleware, `revalidate`, server actions, or anything that needs a request.
- `images.unoptimized` means `next/image` acts like a plain `<img>` (used in
  `InfoClientPage` for the signature). Remote images must be plain `<img>`.
- `trailingSlash: true` is why `.htaccess` rewrites `/path/` → `/path.html`.
- `postcss.config.mjs` registers `@tailwindcss/postcss`; Tailwind v4 has no
  `tailwind.config.*` — theme tokens are plain CSS variables in `globals.css`.

### TypeScript (`tsconfig.json`)

- `strict: true`, `target ES2020`, `moduleResolution: "bundler"`,
  `jsx: "react-jsx"`, `resolveJsonModule: true` (Top-level JSON imports such as
  `ascii-frames.json` and the message files rely on this).
- Path alias: `"@/*": ["./src/*"]` → use `@/app/...`, `@/lib/...`.
- `exclude: ["node_modules", "web"]`.

## 3. Build output layout

```
next build
  → out/                       # deployable static site
       index.html              # /
       es/index.html           # /[locale] for each locale
       es/blog/index.html
       es/blog/<slug...>/index.html
       es/obras/<book>/index.html
       ...
       _next/static/...        # JS/CSS chunks
       images/, fonts/, *.png, x-public.asc
       404.html
       robots.txt              # generated by next-sitemap (postbuild)
       sitemap.xml
       sitemap-0.xml
       .htaccess               # copied from public/
next-sitemap (postbuild)
```

Rules:
- Files in `public/` are copied verbatim to `out/` at the same paths.
- `robots.txt`, `sitemap.xml` and `sitemap-0.xml` are **generated**; never
  add source copies in `public/` or `next-sitemap` may skip/override them.
- To change `.htaccess`, edit `public/.htaccess` and rebuild (it is copied).
- To change the domain in the sitemap, edit `next-sitemap.config.js` `siteUrl`.

## 4. Sitemap & robots — `next-sitemap.config.js`

```js
module.exports = {
  siteUrl: 'https://xscriptor.com',
  generateRobotsTxt: true,
  sitemapSize: 10000,
  exclude: ['/api/*', '/blog/post'],  // legacy paths; safe to trim
};
```

- `postbuild` regenerates `robots.txt` (allows crawlers, points to the sitemap)
  and the sitemaps.
- The `exclude` entries are historical (no API or `/blog/post` route exists).
  Removing them is safe but low-value.
- Per-page priorities/`changefreq` are not customized.

## 5. Security headers

Two header files are shipped because the site can be hosted on either Apache
(primary, via `.htaccess`) or a `_headers`-aware platform.

### `public/.htaccess` (Apache)

- **Static rewrite** for `trailingSlash` output:
  ```apache
  RewriteEngine On
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^(.*)/$ $1.html [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^ /index.html [L]
  ```
- **Headers** (via `mod_headers`):
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: SAMEORIGIN`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), interest-cohort=()`
  - `Content-Security-Policy: default-src 'self'; script-src 'self'
    'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
    font-src 'self'; media-src 'self'; connect-src 'self'; frame-ancestors
    'self'; form-action 'self'`
- **Sensitive file blocking**: `<FilesMatch "\.(env|git|json|lock|md|mdx)$">
  Require all denied</FilesMatch>`.
- **Cache-Control** (`mod_expires`): webp/jpg/png/svg and woff2 → 1 year;
  css/js and mp4 → 1 month.
- **Compression** (`mod_deflate`): html, css, plain, xml, js, json, svg.

> `'unsafe-inline'` in `script-src`/`style-src` is required by the Next.js
> static export (inline theme script, inline styles). A nonce/hash CSP is not
> possible without SSR. If you add a third-party script, you must extend the CSP
> explicitly.

### `public/_headers` (Netlify/Cloudflare Pages style)

```
/*
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: geolocation=(), microphone=(), camera=()
```

Note the intentional differences from `.htaccess` (`DENY` vs `SAMEORIGIN`, no
HSTS/CSP here). Keep both in mind: which one applies depends on the host.

## 6. Hosting

- Target: **static hosting** (Apache/Hostinger being the primary environment
  given `.htaccess`). Any static host works if it honors `trailingSlash`
  routes (Netlify/Cloudflare/Vercel static, GitHub Pages with rewrites, etc.).
- Deploy = upload the contents of `out/` (including `.htaccess`).
- No build step on the server; no Node process.
- `public/x-public.asc` is fetched at runtime by `PublicKeyCard` — ensure it is
  present in the deployed output (it is copied automatically).
- `public/images/**` is large (pre-rendered book backgrounds: 72+31+30 frames).
  Consider CDN/caching; the `.htaccess` already sets 1-year caching for images.

## 7. Validation checklist before shipping

1. `npx tsc --noEmit` — type check (authoritative; `next lint` may be flaky).
2. `npm run build` — must succeed and generate `out/` with `robots.txt` and
   `sitemap.xml`.
3. Spot-check `out/es/index.html`, one book route, one article route.
4. Confirm `.htaccess` and `x-public.asc` exist in `out/`.
5. Verify both themes and `<768px` on the changed pages.
6. Verify `prefers-reduced-motion` behavior if you touched animation.
7. Never commit secrets; there are none in this repo by design.

### Common build failures

| Symptom | Cause / fix |
|---------|-------------|
| `useState is not a function` during export | A Server Component imported a client component directly from `@xscriptor/xcomponents`. Import via the `"use client"` barrel instead. |
| Missing page during export | A route lacks `generateStaticParams` or reads a file that is not present for some locale. |
| Blank book frame | Background frame count ≠ `TOTAL_BG`/`bgConfig.total`. |
| Sitemap missing | `postbuild` did not run; run `npx next-sitemap` after `next build`. |
| Type error on JSON import | `resolveJsonModule` disabled or import path wrong. |
| Stale sitemap/robots | A `robots.txt` was added to `public/`; remove it and rebuild. |
